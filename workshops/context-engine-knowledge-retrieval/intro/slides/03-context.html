Why context engineering · Definition

Context engineering is what the model knows. It fails three ways.

Prompt engineering is how you ask. Context engineering is everything else in the window when the model answers: the instructions, the tools, the knowledge you retrieve, and the memory you carry. Get it right and the model has what it needs, and nothing it does not.

01 · Discovery cost

Tokens burned relearning your schema.

No map of the data, so the agent lists indices, reads mappings, and guesses queries on every question.

02 · Interpretation

Does "arr" mean revenue or array length?

Without business meaning the model guesses. A wrong guess is a confident, wrong answer.

03 · Silos

What one agent learns, no other agent gets.

Knowledge lives in one session and disappears. Quality does not compound and cost does not fall.

Context engineering is the discipline of deciding what goes into the model's context window on each call. The prompt is only one piece.

The highlighted band, retrieved knowledge, is where this workshop lives: what the agent knows about your data before it starts working.

Three failure modes when that band is empty:

  • Discovery cost: every question pays to relearn the schema.
  • Interpretation: in our dataset the revenue field is literally called arr. Models read that as "array".
  • Silos: nothing learned is shared across agents or sessions.
