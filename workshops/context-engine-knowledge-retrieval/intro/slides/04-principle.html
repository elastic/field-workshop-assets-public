Why context engineering · Design principle

Precompute what is durable. Keep what is volatile live.

Durable · precompute it onceWhat each index holds, what fields mean, how indices join, which queries work.
Volatile · query it liveThe rows themselves: today's tickets, this quarter's renewals, the current churn scores.

The design principle behind the Context Engine: split what you know about your data into two kinds.

Durable: the structure and meaning of the data. Which index holds accounts, that arr is revenue, that customer_id joins to account_id. That rarely changes, so work it out once, ahead of time.

Volatile: the rows. Tickets open today, renewals this month. Always query that live so answers stay current.

Multi-color cubes are raw data; blue cubes are processed, ready-to-use context.
